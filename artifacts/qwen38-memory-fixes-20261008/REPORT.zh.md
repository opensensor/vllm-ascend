# Qwen 310P：全部 P1 内存问题的离线修复

[审计](../qwen38-memory-audit-20261008/REPORT.zh.md)中的十项 P1 均已有具体修复或可选缓解路径，并有 CPU 回归测试。
本次没有启动、停止、热切换或修改服务器，也没有运行 NPU 工作负载。所有改动仅通过离线验证，尚未通过硬件验收。

## 改动与默认行为

| 项目 | 实现 | 默认与验收要求 |
|---|---|---|
| A01 QSA K/V | 显式批处理查询块生效；固定形状的共享分组并集避免动态输出规划与重复分组读取。 | 默认仍为 64 查询的批处理收集；两种替代路径需硬件测量。 |
| A02 MTP 计数 | 显式 W8A8 分组草稿路径在不超过八行时可直接捕获；大批次仍使用 eager 路径。 | 默认关闭，要求显式量化分组权重并完成预处理。 |
| A03 PLE 行数据 | 有界常驻锁页主机缓冲区、异步 H2D，以及主机复用前的 DMA 完成等待。 | 默认关闭，需指定容量。 |
| A04 GDN 计划 | 新元数据保存不可变 CPU 调度边界，供每步分块计划复用。 | 默认生效；没有匹配镜像的旧调用方保留回退。 |
| A05 Mamba 计数 | 复用 bookkeeping 已读回的原始采样结果；在丢弃过滤前计数，匹配请求顺序后仅消费一次。 | 仅同步 Qwen MTP/PLE 生效；异步或身份不符仍回退。 |
| A06 FULL 回放 | 可选完成事件明确前次回放、主机参数修改、设备更新及回放就绪顺序。 | 默认保留流同步；事件路径需硬件顺序与吞吐验收。 |
| A09 紧凑表 | 每组锁页缓冲区直接写入常驻设备表，删除临时设备张量及额外 D2D。 | 紧凑映射表默认生效。 |
| A19 MoE 路由 | 每分块结束临时张量生命周期；显式暂存预算限制分块；可选直方图计数替代路由/专家比较矩阵。 | 每分块生命周期修复默认生效；默认分块和比较计数不变。 |
| A22 GDN WY | 复用连续 key；value、gate、beta 及扩展 key 的布局转换与 FP32 转换合并。 | 默认生效；FP32 累加及循环状态不变。 |
| A24 HC 操作数 | 投影类型一致且无梯度时，可复用缩窄操作数。 | 默认关闭；保留 FP32 门控均值、梯度及类型不一致回退。 |

另修复非均匀 GDN 分支中未定义的 `seq_lens` 和未调用的 `is_pinned` 方法。
Mamba 连续且不重叠的复制不再克隆；完全自复制直接跳过；重叠或带步长的视图仍保留克隆保护。
没有替换原生内核、权重、选择策略、图像处理器、缓存容量或启动器。
快照与事件由模型层或 runner 实例持有，没有新增环境变量或可变模块全局状态。

## 逻辑容量与限制

以下是 TP4、2,560-token 分块的逻辑估算，不是 DDR、温度或服务性能实测：

- 批处理 QSA 查询块显式设为 8 时，K/V 暂存由 129 MiB 降为 16.125 MiB；总逐查询流量不因此减少。
- 固定并集查询块 8 的容量为 4,104 组，K/V 暂存约 16.047 MiB。每个有效分组只读一次，
  但填充仍占空间。重叠较少时 QK/PV 工作量可能约增八倍，验收前不能启用为默认。
- PLE 主机容量 2,560 每 rank 占 12.5 MiB；必要 H2D 仍然是 12.5 MiB，不宣称消除传输。
- 128-MiB MoE 逻辑预算推导更小分块，准确值见 [bounds.json](bounds.json)。
  不含内核私有工作区、权重、调用方缓冲区或碎片，不是设备总内存上限；分块变小可能降低吞吐。
- 4/12 本地头几何的 CPU 算子跟踪中，FP16 WY 布局克隆由五次变为两次，
  去掉的 key、value、beta 复制每层每分块约 10.06 MiB；仍需确认 NPU 降低方式。
- HC 保存操作数由 100-MiB FP32 可变为 50-MiB FP16，并避免重复缩窄；门控均值仍用 FP32。
  总峰值与图池分配变化未验收。

必要屏障、复制重叠保护和 FP32 状态均保留。已有 94°C 暂停、85°C 恢复控制器仍处于待执行状态，
其冷却效果需要硬件验证。本次没有新的吞吐、温度、窗口容量或 1M 上下文结论。

## 验证和延后执行

主分支聚焦 CPU 套件通过 **307 项**，一项现有测试因缺少 `msmodelslim` 跳过，详见
[offline-tests.log](offline-tests.log)。测试覆盖分区元数据、复制别名、原始接受计数与丢弃过滤、
快照顺序与异常清理、锁页缓冲区生命周期、图就绪边界、路由归属、因果尾部、HC 精度及 4/12 头 WY。

本机正常 UT 引导因已安装 vLLM 缺少 `vllm.third_party.flash_linear_attention` 无法加载，
直接 MTP 测试导入还缺少 `torch_npu`。聚焦测试使用 CPU 导入和 AST 隔离运行真实生产函数。
模拟事件与隔离函数不能证明硬件正确性；离线限制下没有运行整个仓库或 NPU 套件。

另在本地冻结服务源码上应用并编译 [兼容补丁](audited-runtime-compatibility.patch)，
只适配 QSA 策略两返回值与主分支三返回值的上下文差别，不改变旧接口。
冻结源码检查通过 **75 项**，一项主分支专属策略测试排除；补丁和文件指纹见 [runtime-validation.json](runtime-validation.json) 与
[runtime-tests.log](runtime-tests.log)。冻结版本没有早先的并行收集配置，因而排除主分支专属策略测试。
补丁没有部署。已核对固定 vLLM 提交的 `SamplerOutput` 是 dataclass，替换采样张量保留 logprobs。

要求的 `bash format.sh ci` 因全仓既有 Ruff、拼写、Clang、Markdown 和禁用导入问题及保留补丁哈希的拼写误报失败；
仅在隔离检查目录修改的 144 个无关文件已恢复。本次文件检查另见 [scoped-checks.log](scoped-checks.log)。
原样补丁、指纹及诊断日志单独跳过不透明哈希和原样诊断的拼写检查，范围见 [raw-checks.log](raw-checks.log)。
Python 编译和本次 Ruff 检查通过。没有进行 dummy 或真实权重服务验收。

[queued-profiles.json](queued-profiles.json) 仅保存禁用的局部配置覆盖，不是启动器或启动授权。
