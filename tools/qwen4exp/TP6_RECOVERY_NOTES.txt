Hang and repair
---------------
The resident-v5 shared-memory broadcast warning was a downstream symptom.
Rank zero's producer held the torch_npu allocator lock while waiting for its
host task queue to record an event. The HC launch callback running in that
queue cleared a captured tensor vector and waited for the same allocator
lock. Other ranks waited for the next command. Native/Python stacks were
saved under hang-v5 before terminating that deadlocked session.

native_producer_bridge.cpp retains tensor arguments until successful host
queue drain, then releases them on the submitting thread. It records the
consumer stream for every allocation before enqueueing. Failed submissions
retain their owners. ProducerHCResidual rejects graph capture; this bridge
is for eager HC prefill, not captured decode. Kernel arithmetic is unchanged.

The retained build is hc-producer-v3 with qwen_hc_residual_producer_v1.
An earlier build used a mismatched kernel entry and was rejected before launch;
its session was retired and replaced. No firmware or driver was changed.
The host's canonical restore.py now selects install-hc-producer.py. The old
restore script is archived as restore-before-hc-producer.py.

Reproduction and controls
-------------------------

and OPP environment. Use a fresh service run directory and collective owners.

  python3 launch.py NEW_VERSION
  bash run.sh restore.py resident-NEW_VERSION

The HC/PLE restore includes loaded-weight and six-request checks. The grouped
state optimization is a separate qualified opt-in after that restore:

  bash run.sh -m tools.qwen4exp.apply_tp6_state \
    --run-root <root>/resident-NEW_VERSION --build <root>/mamba-resident-v2 \
    --output <root>/resident-NEW_VERSION/state-install.json

Installation starts in verification mode. Run six concurrent completions that
cross 128-token checkpoint boundaries, then use the same command with
--action on and a fresh --output path (no --build needed). Fast mode rejects
activation without six-row and real boundary-copy verification. --action off
restores CPU copy dispatch; it retains graph and kernel owners for safety.
The already-loaded private v1 operator must not be re-registered; the resident
v2 bridge uses the same kernel ABI under a separate operator namespace.
