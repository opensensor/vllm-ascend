# Qwen 内存传输、检查点与通信候选优化

[英文报告](REPORT.en.md) · [后续验证说明](RUNBOOK.zh.md)。

五个后续方向均已实现离线代码或显式候选。没有启动、停止、修改或测试
服务。只在服务主机编译原生代码，没有打开 NPU 设备、加载动态库或执行
内核。吞吐、功耗和温度收益尚未测量。

## 交付内容

| 方向 | 实现 | 限制 |
| --- | --- | --- |
| 传输统计 | 检查点复制方向、逻辑字节、归档交换、CoW、主机溢出与恢复、主机耗时和同步原因；可选 runner 与 MoE 记录 | 检查点累计计数默认开启，时间明细与额外钩子需显式启用 |
| 检查点批处理 | 各组失效与 CoW 共用一次必要同步，各组槽位复用共用另一次同步 | 显式候选；跨阶段仍保留屏障，回收此前已批处理 |
| GDN 状态布局 | 融合选槽、冷状态清零、转置与最终状态写回，直接使用 H/O 原生布局 | FP32，128 × 128，最多四条序列与 48 个值头 |
| W4 元数据复用 | 每个专家与输出块只加载一次 scale、offset、sum，跨 M=32 行块复用 | 显式模板候选；默认调度与已有 L1 权重复用不变 |
| TP 通信流水 | 预填充中，一个块的归约与下一块的计算重叠 | 每块 1,024 token，最多两个在途块，decode 图保持原路径 |

统计不会读取张量值、调用 `item()` 或增加设备同步。字节是提交的逻辑
载荷，主机时间是提交或阻塞时间，不是异步内核耗时。每个启用的 ledger
最多保留 256 条带时间戳记录。`resident_status` 返回 rank/PID 与各级
统计；离线比较器要求四个 rank 完整、PID/配置未改变且累计计数不下降。

当前覆盖检查点、compact table、PLE history、MTP token 回传、显式 prefix
同步和 W4 TP 调用。算子内部 DMA、通用 runner 元数据、attention collective、
图重放任务与分配器流量仍需 NPU profiler。Python 图计数反映 capture/dispatch，
不能冒充每次重放的真实设备任务计数。

批处理不修改缓存保留、归档容量、溢出策略、状态归属与捕获的存储地址。
base runner 更新后和 admission 阶段分别建立同步边界；空更新与命中不增加
同步。初始同步失败不会改动检查点，后续复制失败不具备原子回滚能力。

GDN 保留原缓存布局和 FP32 状态。冷状态直接清零，不读取过期 NaN；热状态
仅转置。原生 8 × 8 标量转置使用每核 512 字节 UB，可能更慢，须实测。
钩子只作用于自定义 Qwen 的 `_GDNAttention._native_delta_rule`，包括混合批次
的非推测分支；decode 与推测状态仍原地更新。设备 slot ID 依赖调度器保证
范围有效、写回槽唯一，必须在设备集成验证中检查。

W4 不改变激活量化、INT4 乘法、FP32 校正顺序、FP16 边界与非本地输出清零。
候选拒绝 decode/routed ID、旧 metadata lane、其他专家数量或非法形状。
最大 N=160 元数据缓存额外使用每核 19,200 字节 UB，M=32 静态 UB 合计
141,632 字节；这不是设备容量实测。原内核已经跨行块复用 L1 中的打包权重。

TP 将一次大 collective 换成多次小 collective，可能增加 HCCL 开销。
2,560-token MoE 调用变成三次归约。所有 rank 必须使用相同分块和通信顺序。
TP-sharded shared expert 在归约前相加，拒绝 replicated 策略。分块可能改变
GEMM 数值；未声称跨层、attention 或 decode 图通信重叠。

## 修正此前 WY 钩子

此前 fused-WY 候选修改 upstream GDN 的 alias，但自定义 Qwen 不调用该路径。
现在通过真正的 Qwen 方法传递回调，新增执行、状态 IO 与异常恢复回归测试。
旧内核组件验证不能证明模型集成。旧报告保持历史快照，后续服务验证应使用
本次修正后的 runtime；WY manifest 也纳入模型文件指纹。原生 WY 接受服务 gate 的 FP16 beta，
按参考路径将已舍入值拓宽为 FP32，后续组件验证也使用此类型。

## 验证证据

- 聚焦 CPU 测试：**341 项通过，一项因缺少 `msmodelslim` 跳过**。
- 状态内核以有界 CPU DMA/vector stub 编译执行，覆盖 1/12/48 值头、四序列、
  乱序 slot 与冷状态 NaN；FP32 数值和参考一致。stub 的事件为空操作。
- 检查点 CoW 链、阶段同步次数、失败保护、复用、runner staging、空更新通过。
- TP 测试覆盖 shared/routed 相加和有界依赖，不模拟 HCCL 或证明实际重叠。
- W4 测试覆盖 metadata 布局、形状/类型拒绝和 tiling 参数，Cube/事件待设备验证。
- CANN 9.1.0 dav-2002 主机编译通过：两个设备二进制、三个入口与一个版本化 bridge。
  源码指纹与编译记录一致，未加载或执行。
- 扩展测试出现四项既有生命周期错误：CPU 环境缺少
  `torch_npu.float4_e2m1fn_x2`。未修改的父提交 `3802a6e54` 同样四项失败、
  16 项通过；保存了双方日志。
- scoped hooks 与全仓库格式检查结果见 [验证元数据](validation.json)。
  没有声明全套测试或 NPU 验证通过。

[逻辑字节估计](logical-bounds.json) 不是总线实测。在 TP4、四序列、每 rank
十二值头时，状态为 3 MiB；去除中间 IO 后每层估计读写从 30 MiB 降至
12 MiB，不含 H/O、WY、输出与卷积，真实 DDR 行为可能不同。

## 待授权设备验证

使用完整 runtime，逐个验证内核、FP32 最终状态、cold/warm prefix、C1/C2/C3、
混合批次、fresh/cached image、取消与 prefix CoW。保持 94°C 暂停、所有核心
降至 85°C 再恢复、96°C 独立 cutoff；热暂停期间不得切换或重新捕获图。
同步记录四个 rank 的 memcpy 方向/字节、事件与 HCCL 和温度时间线。
减少复制次数不能单独证明降温。

按用户离线要求，dummy、真实权重、图重放、EP、MTP 接受率、图像、容量、
性能与持续热稳定门禁均未执行。代码保留图像能力，但本次没有新增图像验证
或容量声明。FlashComm1 不在此 profile 内；仍暂缓启动服务。
