# 压缩器状态页打包候选

本文记录此前的离线阶段；后续硬件验证信息见 [硬件源文件记录](HARDWARE_SOURCE.json)。

[US English summary](IMPLEMENTATION.md)。

## 实现内容

已离线实现每个 32-token 状态页存放八个四-token 压缩池。状态保持 FP32，
压缩仍每四个 token 一次，注意力逻辑页仍为 640，填充小页仍为 40 KiB。
默认保留四-token 页；在模型构建时显式配置：

```json
{"ascend_glm_kpool_state_block_size": 32}
```

该设置只接受 310P、四-token 压缩和每 token 256 个 FP32 状态元素。
目标及草稿状态层都读取该设置；MTP1 的保守窗口为 33 token。
无效配置在缓存分配前拒绝，不改变压缩精度或推测接受规则。

普通与驻留压缩写入器都按物理状态块大小寻址，只收集所需的四行压缩池，
并按真实填充页跨度写回。保持先读取旧状态再写入、负 slot 掩码、请求隔离和
推测尾部保留。旧的单池页布局保留原 gather 调用。
元数据与缓存块大小不一致时会报错；不引入模型运行器或调度器补丁。

## 原生整数内核

增加精确的带符号除以 32，入口更新为 `glm_integer_divide_v2`，Python
帮助程序和构建来源记录共同标识该版本。准入拒绝旧入口或缺少除以 32 的验证，
要求 INT32/INT64、符号极值、独占填充及变化输入图重放，在
2、8、640、1,280、2,560 行上验证。

驻留写入器的私有改写支持新的商复用，也保留对旧表达式的兼容。
新驻留帮助程序加载前必须重建内核并通过硬件门控，不能复用旧 v1 二进制。
本轮没有编译或执行 CANN 内核。

## 内存预测

历史 TP4 + MTP1 几何下，1,280 调度预算、131,072 上下文的状态准入从
322 个 ID 降为 42 个，总 ID 从 536 降为 256；每卡最低缓存准入从
4.171142578125 降为 1.9921875 GiB，预计减少 **2.178955 GiB**。

按比例分配缓存不会因此自动减少实际缓存预算。实际分配量和图/工作区预留
仍需完整每卡内存账本。新布局需要重新分配缓存，不能热替换到已有四-token 池。
预算工具增加 `--state-block-tokens 32`，并把几何加入上界匹配检查；旧布局的
预算不能证明新布局可行。图、临时、外部工作区、碎片和安全上界不完整时，
工具仍输出 `offline_feasible: false`。

## 验证与限制

- 交付工作区的 **302 项针对性 CPU 测试通过**，使用独立 token 历史对照真实
  普通、压缩、原生改写和绑定写入器。
- 覆盖完整 1,280-token 块、大批量多请求、空请求、部分续填、单-token 解码、
  页边界、640 对齐前缀复用、请求/页回收，以及 MTP1 拒绝后重写已完成的池。
- 覆盖 FP16/BF16 键缓存、负 slot、带毒的 40 KiB 页、非零存储偏移，以及状态
  与索引视图共享物理分配。包括填充区的字节级比较通过。
- 包含之前性能队列的隔离工作树中 **1,764 项 CPU 测试通过**；六项警告来自
  本地依赖弃用及不可用 NVML。Ruff 和 Markdown 检查通过。
- 首轮全量检查发现测试缺少 `Path` 导入，修正后完整通过。
- 无 NPU 编译、图捕获、服务器请求、语言质量结论、实测内存或速度提升。
  本轮没有启动、恢复或探测服务器。
