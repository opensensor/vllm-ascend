Implementation and qualification
  The pinned W4 path converts both gate/up operands to FP32, computes SiLU,
  multiplies, and narrows to FP16. The new path splits before conversion,
  retains the original FP32 SiLU, and uses an owned native vector kernel for
  up conversion, FP32 multiply, and FP16 narrowing. It preserves the qualified
  310P saturation/NaN conversion behavior and does not approximate SiLU.
  At 20480 routed rows it avoids materializing a 50-MiB FP32 up operand and a
  50-MiB FP32 product. These are tensor payloads, not measured allocator savings.

  Admission: eager dense-ND contiguous FP16 [2560..20480,1280], FP32 compute,
  FP16 output, no gradients. Short batches, capture and unsupported geometry,
  layout or dtype use the original expression. Descriptors are reused without
  eviction. Failed launches retain their exception/resources and block reuse.
  Shadow mismatch returns the reference and disables the candidate.
