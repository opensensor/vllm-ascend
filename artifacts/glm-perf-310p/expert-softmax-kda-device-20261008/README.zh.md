# GLM 三项优化：设备验证

本批实现专家 Cube 读回同步与路由 DMA、QSA 多头 softmax 批处理，以及
KDA 满块分数矩阵批处理。均已在服务使用的 CANN 9.1.0 编译并验证，
保留原有精度边界与检查点值。QSA 每核增加 256 B UB，其他项不增加。

| 项目 | 原版本 | 新版本 | 算子测量示例 |
| --- | --- | --- | --- |
| 专家 prefill down | v985 | v995 | W3：7.709 → 7.140 ms |
| QSA 稀疏注意力，640 行 | v991 | v996 | 28.146 → 23.964 ms |
| 完整 KDA，640 token BSND | 行批处理 | 矩阵批处理 | 17.751 → 10.894 ms |

四个专家候选各通过 30 个独立用例、12 个真实权重用例、60 个父版本边界
对比及三次变化输入图重放。QSA 通过 36 个精确比较；四个服务 rank 各
通过 24 个受限验证用例。KDA 的 17 个有限用例全部 12 个输出逐字节
一致，64/640 token 变化输入图重放通过；两个父版本本身非有限的用例
不计入有限验证数。

最终 prefill 选择：6,400 token 冷启动中位数 56.160 →
53.954 秒，减少 3.93%；C1 中位数
10.177 → 10.164 tok/s，变化 -0.13%。
联合 v6 候选的 C1 回归，未保留。

最终服务比较使用相同配置的三批新进程，先预热，每次请求清除前缀
缓存。进程间漂移与小样本限制了性能结论强度。6,400 token 请求各重复两次；C1 用三次 128 输入/128 输出请求
统计完整生成间隔。三组均使用新 KDA。v6 的 C1 中位数
9.73 tok/s，低于父版本 10.18，因此最终 v7 保留 decode v984、QSA v991，
只启用新 prefill v995 与 KDA；不能将各算子收益直接相加。合成 token 用于测速；文本 smoke
仅验证 API 执行，语言质量仍由用户检查。

重复热切换存在图内存生命周期限制：新 worker 首次选择正常，多次
切换以及完成父版本负载后的第二次切换均出现 242 MiB 捕获 OOM。
释放暂存投影缓冲仍不足以解决。最终在新进程中直接保留 prefill 候选，
与已完成的父版本负载做分进程比较，保留原 311,040 上下文、
四个并发槽与 0.965 内存设置。失败、恢复与最终未暂停的健康状态均留档。

CPU GLM 独立测试 1,587 项通过，修改文件的格式检查通过；全仓检查的
既有错误见离线阶段记录。详见 [英文报告](README.md)、[运行手册](RUNBOOK.md)
和 [机器摘要](SUMMARY.json)。

最终选择另通过四个同时进行的完整 128 输入/128 输出请求，执行图大小 8，
无需重新捕获；此项没有配对 C4 性能基准。
