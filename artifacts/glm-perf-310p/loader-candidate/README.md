# GLM W2 opt-in safetensors filter: metadata audit

**Audit date:** 2026-10-01. **Status:** direct NPU math checks complete; vLLM serving is deferred.

The candidate `--load-format glm_w2_filtered` keeps `DefaultModelLoader` file discovery and the W2 model's weight placement. It intercepts the lazy safetensors iterator before `get_tensor`, skipping peer-owned decoder expert tensors whose names exactly match `model.language_model.layers.{L}.mlp.experts.{E}.{gate_proj|up_proj|down_proj}_{codes|scale}`. When the checkpoint index is present, it also skips superseded local expert tensors whose final indexed shard is a later overlay. It leaves dense, vision, and unwired MTP tensors on the default path. The Qwen EP filter alone does not match these `_codes` and `_scale` suffixes.

## Exact checkpoint coverage

I read only `/srv/ai/models/GLM-5.3-Flash-W4through32-noclip-310p/model.safetensors.index.json`, `config.json`, and the JSON header of each indexed shard over read-only SSH. The index selects 33 of 33 `.safetensors` files and 75,575 **logical** tensors, totaling 151,700,647,612 payload bytes (141.282 GiB). Config geometry is 45 decoder layers, three initial dense layers, 288 routed experts, and one MTP layer at index 45. The loader's TP-contiguous ownership gives 72 experts per rank; this matches `glm5next_w2.moe.ep_expert_range` for TP4.

The selected files contain **10,368 additional physical header entries** (11,041,505,280 bytes) in original shards 14–17 for layers 27–32. The index points those same keys to six later `w4-overlay-layer-*.safetensors` files. `DefaultModelLoader` selects files with the index but iterates every key in each selected file. It therefore yields the old entries and then the overlays. The candidate now skips the old local entries using the index; peer entries were already skipped by ownership. Every extra key is a recognized expert code/scale name, and the final source for every key matches the index under vLLM's natural shard order.

The indexed logical view alone has 18,144 local decoder tensors (32,912,179,200 bytes) and 54,432 peer decoder tensors (98,736,537,600 bytes) per rank. The table includes the old superseded header entries because they are in the physical shards: 2,592 extra local tensors (2,760,376,320 bytes) and 7,776 extra peer tensors (8,281,128,960 bytes). **No shard is wholly skippable** for any rank: local or non-expert tensors are mixed into all 33 files. The candidate avoids `get_tensor` for 102.239 GiB per rank in total, including 2.571 GiB of superseded local payload. These are header-derived payload sizes, not measured reductions in physical disk reads. Safetensors may map payload pages without faulting them; startup time, page faults, disk bytes, and RSS need measurement.

## Contract and guard review

- The recorded server uses `Glm5NextW2ForCausalLM` through an `hf-overrides` architecture override; the raw checkpoint architecture is `Glm5NextForConditionalGeneration`. The candidate checks the effective architecture, `glm5_next` / `glm5_next_text` config types, and integer expert/layer geometry before filtering. A launch without the architecture override should fail closed.
- The candidate derives ownership from the same `_ep_rank_size()` and `ep_expert_range()` as the W2 bank and placement code. The model's `_place_streamed_expert` already ignores peer tensors after iteration, so removing those tensors from the iterator preserves the intended rank-local bank contents. The candidate leaves layer 45 untouched because the W2 model's MTP skip occurs in `load_weights`.
- The candidate checks source model path, revision, empty prefix, and absent subfolder, and refuses non-safetensors files, eager/prefetch loading, and multithread loading. It delegates shard selection to the default loader. It uses the checkpoint index only to discard exact expert keys whose indexed shard differs from the shard being read. The opt-in registration leaves the ordinary `safetensors` loader unchanged.
- The server loaded all 33 shards and opened the API once with this load format. Local bank digests and non-expert parameter parity have not been checked. The CPU tests exercise synthetic headers, including an old tensor followed by an indexed overlay; the exact-checkpoint metadata audit verifies file selection, per-rank completeness, stream byte counts, and final source order.

The active filtered and baseline launchers had forced `ascend_glm_mhc_fp16_state=true`, an experimental speed mode that changes the golden mHC state math. Both now use the model default, which rounds mHC state to BF16 precision while storing it in FP32 on 310P. A direct NPU check matched BF16 result bits and showed the FP16 mode clips a 70,000-valued state to 65,504. The three focused rounding tests pass. Direct NPU causal-convolution checks showed dirty cache slots are cleared for fresh requests at lengths 1, 5, and 26. Native 26-token, 16-head flash attention repeated bitwise and differed from a causal FP32 reference by at most 0.000389. Direct KDA chunk and mHC Sinkhorn checks also passed their focused references. These checks narrow the fault but do not establish complete model or golden-checkpoint parity. In particular, this W4/W2 checkpoint is a separate quantization of ZAI FP8, while the earlier GPU golden used NVIDIA NVFP4. The user has deferred all further NPU use, including vLLM serving.
