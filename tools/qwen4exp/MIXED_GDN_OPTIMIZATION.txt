Experiments and retained implementation
---------------------------------------
Private resident real-bank gates compared baseline, small and local_count
expert schedules at 5150 routed rows, both projections, balanced/skewed routes,
zero/all local routes and all four ranks. Every output was exact, but timing
differences did not justify changing the installed local_count schedule.

Generic scatter was exact but much slower on 310P: roughly 9--10 ms versus
0.56--0.63 ms for indexed assembly at 515 rows. It was never installed.

The retained mixed_gdn_merge candidate concatenates the speculative and prefill
outputs, then gathers them into token order. A device-side inverse permutation
is built once per step and shared by the GDN layers through their metadata.
The builder's disjoint complete partition and immutable per-step indices are
the contract; arbitrary interleaved token order is supported. State updates,
gating, convolution and delta-rule arithmetic remain exactly the original.
Pure decode never enters the changed method. No normal-path device readback
or synchronization is introduced, and each returned output owns its storage.

Private tests on every rank covered 515/518/521/1923 rows, 3/6/9 speculative
rows and shuffled partitions. Gather took about 0.05--0.075 ms at 515 rows
and 0.11--0.12 ms at 1923 rows. These are isolated synchronized timings.
The subsequent real-weight mixed run checked 1512 merges per rank, 6048 total,
bit-for-bit with zero mismatches. Verification always returns the reference;
a mismatch disables the candidate without raising during rank collectives.
Verification is disabled after admission for normal serving.

In the comparable early native capture, rank 0 IndexPut totals fell from
83.977 ms / 144 calls to 24.663 ms / 75 calls. The mixed-output indexed writes
were removed; state-cache and WY inverse writes remain. GatherV2 and ConcatD
totals together increased only about 0.42 ms. This establishes the local
kernel improvement, not an equal reduction in request latency.

Reapply and reverse
-------------------
Use the established resident Python and serving tools overlay described in
the runtime runbook. Copy mixed_gdn_merge.py into that overlay. Each control
command needs the current RUN directory and a fresh OUTPUT directory:

python artifacts/qfn-next-profile-20261015/private-gates.py gather --run-root RUN --output OUTPUT
python artifacts/qfn-next-profile-20261015/merge-control.py install --run-root RUN --output OUTPUT

Install starts in verification mode and requires the exact qualified original
method source. Run a mixed prefill/decode workload, inspect all worker checks,
then use merge-control.py on. The on action requires successful live checks on
every rank. off retains the owner but uses indexed assembly; restore reinstates
the original method. Every transition drains the server first and verifies
resident weight/graph/native-owner identity before resuming. No recapture or
server restart is required. This is a resident deployment; after a restart,
restore the qualified stack and repeat admission rather than assuming it is on.

The compare-merge.py, finalize.py and collect-evidence.py controllers reproduce
the comparisons, retained-stack audit and compact evidence collection. Full
raw traces and receipts remain in the dated artifact directories on the host.
