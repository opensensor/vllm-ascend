Draft snapshot fix
  The v14 crash dump contained all_token_ids for the failed first-decode
  request. The pinned Scheduler._make_cached_request_data adds that entry
  when the request was absent from prev_step_scheduled_req_ids. Its runner
  draft getter exposes only the most recent worker batch. A prefill-only
  intervening batch can therefore overwrite drafts needed by the returning
  request, producing the observed missing-worker-drafts exception.

  QueuedScheduleBridge now snapshots actual host drafts before a nonuniform
  batch replaces them, even when the next schedule is prefill-only. Reuse
  requires the same worker request, prompt length, output count and last
  sampled token. Finish/resume, replaced history and fresh invalid drafts
  invalidate snapshots. Missing drafts still fail closed. The unchanged
  device-only continuation path never reads host drafts or caches its zero
  shape reservations.

  Regression tests reproduce the omitted-request sequence and reject stale
  snapshots. Two real concurrent 20.8K/23.1K prefill pairs completed, each
  returning 64 tokens per request; the complete retained audit passed after
  them. Snapshot-hit counters remained zero in those hardware workloads:
  they validate integration, not the formerly failing branch. The final
  prompt-length invalidation guard has host-test coverage only.

Pending-first-sample fairness: host-tested, not hardware-qualified
  The concurrent pairs exposed 5.208 / 5.225 second maximum decoder content
  gaps. The prefill cap currently waits for num_output_tokens > 0, although
  AsyncScheduler has already reserved a pending first sample. Its next large
  prefill may queue ahead of that decode. MixedPrefillBudget now also checks
  num_output_placeholders, preserving stricter limits and restoring config
  after schedule(), including exceptions. The old pure-decode check still
  short-circuits the added scan. Unit tests cover pending and absent samples.
  The prepared shorter before/after hardware test was not run due to the fault;
  no latency improvement from this change is claimed.
