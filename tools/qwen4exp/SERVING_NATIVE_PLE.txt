Runtime architecture and integration
  The established Qwen model combines attention/state-space blocks, MoE and MTP.
  PLE hashes current tokens and two preceding tokens into 16 checkpoint rows,
  each 160 FP16 elements. Existing projection, gate, convolution and residual
  computation remain in the model. The native selector emits the same row IDs;
  the CPU reads a compact receipt, gathers rows into pinned staging, then sends
  one response DMA. The full table is not copied to the NPU.
  Torch's asynchronous host queue must finish before a private ACL producer can
  read its inputs. This adapter explicitly joins the Torch stream; the isolated
  microbenchmark's inputs-ready assumption would be incorrect in serving.
  Input tokens/history are converted to INT64; packed boundaries remain INT32.
  Four request groups are supported; an unsupported fifth padding group falls
  back to the original reader. Prefill >12 tokens also retains the old path.

Performance and accuracy limits
  With verification disabled, warm measured single-request decode was 28.2 and
  28.9 tokens/s in the first two checks. Later complete code/thinking requests
  measured 36.6/31.2 tokens/s, illustrating workload/MTP acceptance dependence.
  The first 128-token explanation completed in 4.707 s including prefill.
  Per-rank recent lookup medians were 1.41-1.85 ms including the Torch join;
  native producer-plus-transport medians were 97-115 us. These are serving
  measurements, distinct from the isolated 40-us producer-poll microbenchmark.
  No controlled end-to-end speedup over baseline has been established.
  Two 32-token greedy completion runs differed late in their text across graph
  recapture, despite exact PLE comparisons. Do not claim token-identical model
  output across those runs or interpret this smoke gate as an accuracy suite.
  No new formal benchmark accuracy score was measured or substituted for the
  existing model evaluation. Exact PLE equality and coherent response checks
  validate this transport integration, not overall model accuracy.
  Cold geometry admission took seconds. Only already-admitted shapes have the
  warm latency above. Hot uninstall is unsupported; retain owners until worker

Runbook (the already qualified host paths are intentional)
  r=/srv/ai/storage/artifacts/ple-host-gather-20261015
  old=/srv/ai/storage/artifacts/npu-collective-qfn-20261014-024609
  py=/srv/ai/venvs/qwen38-w4-test-ce1862/bin/python

  The current API PID is in $r/serving-v1-api.pid. Its private control token is
  $r/serving-v1/control.token. The shared table owner PID is in
  $r/serving-table-v1.pid; its ready descriptor is $r/serving-table-v1.json.
  Leave that process running while admitting workers. Existing native mappings
  retain their own table references, but a dead owner cannot admit new shapes.

  To stop serving, send SIGTERM to the recorded API PID. The existing shutdown
  guard drains inference and closes custom collectives before worker teardown.
  Do not unload the driver or hot-uninstall the native PLE candidate.

  For a fresh start after shutdown, use a NEW absolute run directory:
    nohup bash "$old/start-qfn-engine-control-candidate.sh" \
      --tools-root "$r/serving-source-v1" --run-root "$r/serving-v2" \
      > "$r/serving-v2-launch.log" 2>&1 </dev/null &
  Wait for /v1/models and a successful baseline completion, then install:
    cd "$r/serving-source-v1"
    PYTHONPATH="$PWD" "$py" -m tools.qwen4exp.apply_ple_serving \
      --run-root "$r/serving-v2" --table "$r/serving-table-v1.json" \
      --library "$r/serving-source-v1/libple_host_gather.so" \
      --selector-build "$old/ple-request-build-v1" \
      --output "$r/serving-v2-apply"
  This pauses/drains requests, recaptures graphs and resumes. It initially
  enables exact PLE verification. After successful requests, use the local
  QfnResidentClient to pause, call qfn_cpu_profile_stop with argument
  native_ple_verify_off, and resume; see validate-serving.py for the exact flow.
  Source/build paths are experimental overlays, not an upstream installation.

  After a reboot, first reload the source in the background from the overlay:
    "$py" -m tools.qwen4exp.serve_ple_table \
      --model /srv/ai/models/Qwen3.8-Flash-Next-W4A16-G128-300i \
      --ready "$r/NEW-table.json"
  Use its new readiness file in apply_ple_serving; never reuse stale PID/FD
  metadata. The loader enforces a 48-GiB host reserve. The driver spin setting
  returns to its default zero after reboot unless separately set to 5.
